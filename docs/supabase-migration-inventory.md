# Inventario local de migraciones Supabase

**Alcance:** inspección estática de los archivos presentes en `supabase/migrations/`. No se consultó Supabase remoto. Por tanto, ninguna fila afirma que un SQL esté aplicado o pendiente en el proyecto remoto.

## Clasificación

- **Objetivo de hardening:** `20261002170000`, `20261002170300` y `20261002170400`, después de validar la estructura remota y reconciliar el historial.
- **No activar ahora:** `20261002170100` y `20261002170200` crean el esquema y las policies de comercio; checkout, pedidos, pagos e inventario siguen fuera de alcance.
- **Históricas compatibles solo si el historial/estado lo demuestra:** las migraciones incrementales antiguas de catálogo, alineamiento y grants. No volver a aplicarlas a ciegas.
- **Heredadas/inseguras que no deben ejecutarse:** `20260727000000_set_admin_raw_app_meta.sql`, `20260727123000_add_products_storage_policies.sql`, los snapshots/baselines incompatibles y el fix mínimo obsoleto.
- **Confirmación remota obligatoria:** toda migración con timestamp que pudiera formar parte del historial, especialmente `20260727000000` y `20261002160428`.

Supabase CLI descubre los archivos `.sql` de esta carpeta independientemente de las etiquetas de este documento. No ejecutes `supabase db push` hasta completar la reconciliación de [supabase-migration-reconciliation.md](supabase-migration-reconciliation.md).

## Resumen de aplicación

1. No aplicar los dos baselines (`0001_*`) encima de un esquema remoto existente.
2. No ejecutar `20260727000000_set_admin_raw_app_meta.sql` ni `20260727123000_add_products_storage_policies.sql`.
3. No decidir el estado de las versiones antiguas o `20261002160428` a partir de archivos locales; comprobar el historial remoto de manera manual y de solo lectura.
4. Planificar el hardening de perfiles (1700, 1703, 1704) solo después de reconciliar tablas, tipos, triggers, grants y policies.
5. Mantener 1701/1702 fuera del despliegue hasta una decisión separada sobre comercio. En particular, no activar checkout, pedidos, pagos o inventario.
